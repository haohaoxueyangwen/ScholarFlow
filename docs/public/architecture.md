# ScholarFlow 开发架构与边界

ScholarFlow 是基于 Pi 的科研助手 harness。Pi 负责唯一的模型交互、工具选择、会话和压缩运行时；网页是可选客户端，不是第二个 Agent。

```text
CLI / 可选网页
    ↓
Pi 会话与能力组合（Skills + tools）
    ↓
领域服务：项目、来源、论文、受控笔记和审批
    ↓
可选适配：PDF 解析、文献搜索、LightRAG、Obsidian / Zotero
```

- `packages/scholarflow-pi/`：Pi 扩展、能力、Skill 和运行配置。新增能力优先提供独立 Skill、工具、适配器与测试，不在网页中另建模型循环。
- `scholarflow/`：项目和研究事实、PDF 来源授权、受控写入、笔记、知识索引及本机 HTTP 接口。项目事实、人类笔记、Pi 会话和可重建的 AI 索引是不同层。
- `apps/research-workbench/`：可选网页与精读器，调用相同领域接口，支持文献搜索、PDF 阅读、Pi 对话及审阅笔记。
- `scripts/` 与 `tests/`：本公开开发快照包含可移植安装、运行入口与筛选后的测试；只属于原电脑科研资料和运维任务的脚本/数据不在此快照。

写操作必须绑定明确项目、来源版本和操作者确认；自动索引只处理经批准的笔记，不能将未审阅的模型回答当成研究事实。新的外部 Skill 应核查来源、许可、权限及版本，Skill 指令本身不是安全沙箱。

当前基础能力经过单篇开放论文、指定页码和隔离数据的限定验证：搜索、下载、阅读、审阅、索引和带来源问答可走通。扫描件 OCR、任意全文科研质量、长任务自动压缩、完整外部软件联动、所有升级回滚以及第二台电脑运行尚不能据此视为完成。
